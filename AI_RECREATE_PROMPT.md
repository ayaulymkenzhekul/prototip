# Промпт для ИИ: воссоздать прототип "Смета РК / Цифровой сметчик"

Скопируй весь текст ниже и дай его ИИ-разработчику. Цель: создать максимально похожий на текущий проект интерактивный HTML-прототип.

```markdown
Ты senior frontend-разработчик и UX-дизайнер. Создай одностраничный веб-прототип "Смета РК / Цифровой сметчик" для работы с дефектными ведомостями, согласованием ЕСЭД, распределением СМАКС, осмечиванием и справочниками.

Нужно сделать проект максимально похожим на исходный прототип:
- один главный файл `index.html` с HTML, CSS и JavaScript;
- локальный Node.js сервер `api/server.js`;
- папки `assets/` и `data/`;
- старт командой `npm start`, порт `3001`;
- приложение открывается по `http://127.0.0.1:3001/index.html`;
- язык интерфейса: русский;
- бренд: `Смета РК`;
- ассистент: `Цифровой сметчик`, не использовать название "МЕСАЛИНА";

Используй чистый HTML/CSS/JavaScript без сборщика. Можно использовать inline SVG-иконки. Данные держи в JS-массивах и `localStorage`. Сервер нужен только для раздачи статики и API-прокси.

## Сервер

Создай `api/server.js` на Node.js:

- раздает статические файлы из корня проекта;
- `/` открывает `/index.html`;
- CORS разрешен;
- `GET /api/assistant-status` возвращает JSON со статусом прокси;
- `GET /api/groups?format=tree|flat` читает `data/groups.json`, нормализует группы и строит дерево;
- `POST /api/defect-assistant` принимает `{ message }`, проксирует во внешний ассистент через переменные окружения:
  - `CA_UPSTREAM_URL`
  - `CA_ASSISTANT_ID`
  - `CA_AUTH_TOKEN`
  - `CA_AUTH_HEADER`
  - `CA_AUTH_SCHEME`
  - `CA_COOKIE`
  - `CA_ORIGIN`
  - `CA_REFERER`
  - `CA_ALLOWED_ORIGINS`
- если прокси недоступен, фронтенд должен иметь локальную имитацию ответа ассистента.

## Единый предпросмотр документа ДВ

Это ключевой экран `pg-caDoc`. Он должен выглядеть как рабочий предпросмотр документа:

Layout в обычном режиме:

```text
левая панель справочников/ведомостей | документ | правая панель цифрового сметчика
```

Вверху документа:

- заголовок `Электронная дефектная ведомость`;
- badge статуса;
- подзаголовок `№ ... · Проверка перед осмечиванием / Согласование ЕСЭД / Распределение СМАКС · единый предпросмотр`;
- кнопки:
  - `Редактировать / Закрыть редактирование`
  - `Сохранить`
  - `Проверить`
  - основная кнопка: `Отправить на осмечивание`, `Согласовать ДВ` или `Назначить сметчика`
  - export menu.

Функция `openUnifiedDocumentPreview(dv, mode, returnFlow, options)`:

- нормализует входные данные в `defectCADraft`;
- ставит `caDocPreviewMode = mode || 'draft'`;
- ставит `caDocReturnFlow`;
- включает `caDocReadOnly = !!options.readOnly`;
- если read-only, `caDocEditMode = false`, иначе `true`;
- открывает `gotoPage('caDoc')`.

Функция `renderCADocumentPreview()`:

- если `caDocLeftMode === 'references'`, показывает справочники;
- иначе показывает документ:
  - карточка готовности к осмечиванию, кроме read-only режима;
  - `СМЕТА РК · ЦИФРОВОЙ СМЕТЧИК`;
  - `ДЕФЕКТНАЯ ВЕДОМОСТЬ`;
  - номер и дата;
  - раздел `01. Общие сведения`;
  - раздел `Описание работ`;
  - раздел `02. Работы`;
  - раздел `03. Материалы`;
  - раздел `04. Дефекты`;
  - раздел `05. Приложения`;
  - раздел `06. Комментарии`;
  - раздел `07. Подписи`.

Редактируемость:

- в обычном режиме поля должны быть `input`/`textarea`;
- кнопка `Сохранить` собирает значения обратно в объект;
- можно добавлять, копировать и удалять строки работ/материалов;
- в read-only режиме все поля являются обычным текстом, нет кнопок действий, нет колонок `Действия`, нет карточки готовности.

Read-only режим нужен для кнопки `Открыть полную ДВ` в ЕСЭД и СМАКС:

- открывается только сам документ;
- без левой панели;
- без правой панели ассистента;
- без стадий и вкладок;
- сверху оставить синюю кнопку `Закрыть`;
- кнопка `Закрыть` возвращает на исходную очередь;
- никаких инпутов, сохранения, проверки, согласования или назначения.

## Справочники внутри предпросмотра

В левой панели `pg-caDoc` должны быть вкладки:

- `Ведомости`
- `Справочники`

Во вкладке `Справочники` реализовать CRUD-макет:

- Объекты / Локации
- Материалы
- Работы
- Единицы измерения

Для материалов обязательно показать карточку:

- `Плитка керамическая 300×300 мм`
- код `MAT-001`
- статус `Approved`
- справа карточка редактирования;
- отдельная строка `MAT-D-04` с названием `Плитка напольная 300 на 300`;
- статус именно `Возможный дубль`, а не обычный статус ДВ;
- кнопка `Объединить дубли`;
- после объединения статус должен стать `Объединено` или карточка должна показать связь `MAT-D-04 → MAT-001`.

Важно: статус дубля относится только к разделу справочников, не к самой дефектной ведомости.

- `EXTERNAL_RATES` может загружаться из `data/rates-index.json`.

## Важные UX-детали

- Sidebar можно свернуть.
- Светлая тема по умолчанию, темная может быть как класс `ui-night`, но по умолчанию светлая.
- Все кнопки должны работать хотя бы на уровне прототипа: менять статус, открывать экран, показывать toast.
- Все поля в документе ДВ в обычном предпросмотре редактируются.
- В read-only предпросмотре поля не редактируются.
- Не оставлять пустые огромные зоны на страницах ЕСЭД и СМАКС: контент должен тянуться на доступную ширину.
- В очередях использовать аккуратные SVG-иконки внутри кнопок.
- Кнопки не должны иметь обрезанный или съехавший текст.
- Шапка документа `Электронная дефектная ведомость` должна быть выровнена слева, не по центру.
- Кнопка `Закрыть` в read-only документе должна быть синей и с текстом по центру.
- В бренде и ассистенте использовать `Цифровой сметчик`, не `МЕСАЛИНА`.

## Toast и уведомления

Сделай функцию `showToast(message, type, detail)`:

- появляется справа/снизу;
- типы: `success`, `warning`, `info`, `error`;
- исчезает автоматически.

Сделай `addSignalNotification(title, type, payload)`:

- добавляет уведомление в массив;
- увеличивает счетчик;
- используется при согласовании, возврате, отправке на осмечивание, назначении сметчика.

## Проверка результата

После создания проекта проверь:

1. `npm start` запускает сервер на `3001`.
2. Открывается экран логина.
3. Роль заявителя открывает реестр ДВ.
4. `Создать ДВ` открывает чат цифрового сметчика.
5. Предпросмотр ДВ редактируемый, поля можно менять.
6. Роль Есенов открывает очередь ЕСЭД.
7. В ЕСЭД действия идут вертикально: согласовать, вернуть, открыть ДВ.
8. `Открыть полную ДВ` в ЕСЭД открывает read-only документ.
9. Роль СМАКС открывает очередь распределения.
10. В СМАКС выбор сметчика компактный и раскрывается по кнопке `Выбрать`.
11. `Открыть полную ДВ` в СМАКС открывает read-only документ.
12. В справочниках материалов статус дубля показывается именно в разделе справочника.
13. Везде написано `Цифровой сметчик`, а не `МЕСАЛИНА`.
14. Кнопка read-only `Закрыть` синяя, текст по центру.
15. Шапка `Электронная дефектная ведомость` стоит слева и не съезжает.
```

## Краткая карта текущего проекта

Исходный проект, по которому составлен этот промпт:

- основной файл: `index.html`;
- размер прототипа: около 1.1 МБ;
- сервер: `api/server.js`;
- старт: `npm start`;
- данные: `data/groups.json`, `data/materials-index.json`, `data/rates-index.json`, `data/rates-details/`;

Главная логика находится в `index.html`:

- единый документ: `openUnifiedDocumentPreview`, `renderCADocumentPreview`;
- ЕСЭД: `ESED_QUEUE_ITEMS`, `renderESEDQueue`;
- СМАКС: `ensureSMAXData`, `renderSMAXQueue`;
- справочники: `renderCADocReferences`, `renderAdminPage`;
- каталог работ/материалов: `WORKS_DB`, `MAT_CATALOG`, `RSMB_TREE`;
- хранение: `localStorage`.
