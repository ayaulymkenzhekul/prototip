# UI Rules

## Общий стиль

- Clean enterprise SaaS.
- Светлая тема.
- Основной цвет действий: синий.
- Success: зеленый.
- Warning: желтый/оранжевый.
- Error: красный.
- Карточки белые, аккуратные, без перегруза.
- Таблицы читаемые.

## Запрещенные паттерны

- Большие пустые области без смысла.
- Декоративные кнопки без действия.
- Второй sidebar внутри страницы, если он дублирует главный.
- Текст, который не помещается в кнопку или карточку.
- Старые названия "МЕСАЛИНА" и "Цифровой сметчик" для AI-чата.

## Важные UI-решения из чатов

| Решение | Причина |
| --- | --- |
| "Год сметирования" -> "Год реализации" | Поле относится к году реализации работ, а не только к смете. |
| Номер ДВ: `ДВ-YYYY-MM-XXX` | Номер ДВ должен отличаться от номера сметы/заявки. |
| "Цифровой сметчик" -> "Цифровой ассистент" | Помощник работает шире, чем только сметы. |
| Блок готовности свернут по умолчанию | Не должен занимать первый экран и отодвигать документ вниз. |
| Убрать "Смета РК" из sidebar | Название сужает смысл продукта до сметы. |
| "Открыть полную ДВ" в ЕСЭД/СМАКС read-only | На этих этапах документ смотрят, а не редактируют. |

## Интерактивность

- Все кнопки должны иметь обработчик.
- После действия пользователь должен видеть результат.
- Ошибки показывать через toast или inline message.
- Если данных нет, показывать empty state и следующее действие.
