# Integration

## Текущий принцип

Проект сейчас является прототипом и должен быть готов к дальнейшему подключению backend/API.

## Backend рекомендации

- REST API.
- Swagger/OpenAPI.
- API или файл обмена для ЕСЭД и SMAX уточняется на Discovery.
- Права доступа по ролям.
- История действий на backend.
- Секреты не хранить во frontend.
- Данные ДВ, справочники, очереди и сметы должны приходить с backend в промышленной версии.
- Все ключевые действия должны фиксироваться в журнале аудита.

## Что нужно запросить у backend-разработчика

- Swagger/OpenAPI.
- Base URL тестового сервера.
- Тестовые учетные данные.
- Описание ролей и прав.
- Список статусов.
- Примеры request/response.
- Правила CORS.
- Методы для ДВ, ЕСЭД, СМАКС, сметчика, справочников, файлов и ЦА.

## Важное ограничение

Frontend не должен хранить пароли, токены, ключи и промышленные секреты. Если разработчик спрашивает, есть ли секреты в текущем прототипе, нужно проверить репозиторий перед пушем.

## Целевые системы

Целевыми системами могут быть ЕСЭД, SMAX, ERP, ТОиР, документооборот, архив или иная корпоративная система.

Интеграция должна фиксировать:

- что передавалось;
- когда передавалось;
- кем инициировано;
- какой статус операции получен;
- какая ошибка возникла, если передача не прошла.
