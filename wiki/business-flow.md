# Business Flow

## Основной маршрут

```text
Заявитель -> ЦА Дефектовщик -> ЕСЭД -> СМАКС -> Сметчик -> ЦА Сметчик -> Старший сметчик -> Закрыто
```

## Основной сценарий

1. Заявитель создает ДВ.
2. ЦА Дефектовщик помогает заполнить данные.
3. Заявитель проверяет live-предпросмотр.
4. Ошибки исправляются вручную или через ЦА.
5. ДВ отправляется на согласование.
6. ЕСЭД согласует или возвращает.
7. После согласования ДВ попадает в СМАКС.
8. СМАКС назначает сметчика.
9. Сметчик открывает входящую смету.
10. ЦА Сметчик помогает подобрать сметные работы, материалы и расценки.
11. Сметчик подбирает или подтверждает расценки.
12. Смета закрывается или передается на проверку.
13. Старший сметчик проверяет итог, если это требуется.
14. ДВ и смета выгружаются в целевые системы или архивируются.
15. Процесс закрывается с сохранением истории.

## Возврат из ЕСЭД

```text
ЕСЭД -> На доработке -> Заявитель -> Исправление -> Повторная отправка
```

Правило: возврат требует комментарий.

## Возврат из СМАКС

```text
СМАКС -> Возврат заявителю -> Исправление -> Повторная передача
```

Причины:

- неясное основание;
- проблема с приоритетом;
- недостаточно данных;
- нельзя назначить сметчика.

## Уточнение от сметчика

```text
Сметчик -> Вопрос заявителю -> Ответ -> Продолжение осмечивания
```

## Выгрузка результата

```text
Смета готова / Проверена -> Выгрузка -> Целевая система / Архив -> Закрыто
```

Выгрузка должна фиксировать статус операции. Если интеграция недоступна, результат должен быть сохранен как подготовленный пакет документов или статус операции с ошибкой.
